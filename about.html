Operating principles

How I think about the work.

PRINCIPLE 01

Systems > dashboards.

A dashboard is a UI on top of a system. If the system underneath is broken, polish doesn't help. I start with the plumbing.

PRINCIPLE 02

Outcomes, not artifacts.

I don't count models, pipelines, or dashboards. I count the decisions that got faster and the hours that got given back. The rest is trivia.

PRINCIPLE 03

Scope is kindness.

Vague engagements fail. I'd rather spend an extra week scoping precisely than run a project that ends in a fuzzy outcome and a confused handover.

PRINCIPLE 04

Leave the company stronger than it found me.

Every engagement ends with real documentation, named owners, and a team that can extend the work. Consulting that creates dependency is a failure mode, not a business model.
